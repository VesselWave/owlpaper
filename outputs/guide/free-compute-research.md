# Free compute for Owlpaper

Researched November 16, 2026. Applicant: undergraduate at Austin Community College, Austin, Texas. This is a broad survey of practical routes, not a guarantee of eligibility, capacity, or an exhaustive inventory of temporary promotions. No accounts were created or applications submitted.

## Recommendation

**Capstone update:** The project is an AI safety capstone and the organizer's supplied announcement explicitly invites experiment-funding requests. That is now the most direct route to suitable GPUs. See `capstone-compute-request.md` for a draft. The screenshot's student-Colab advice conflicts with the current Colab FAQ; do not budget premium compute from that offer.

GPU tasks can support training as well as inference, but require Modal packaging, persistent storage and timeout handling. CPU, RAM and storage also consume budget. GPU availability/account eligibility must be checked. [Pricing](https://modal.com/pricing)

1. **Apply for AMD AI Developer Program cloud credit first.** The current offer is $100 credit, and the advertised single MI300X has 192 GB GPU memory. This is the best immediate lead with enough memory and no faculty requirement stated on the offer page. Qualification, region, capacity and payment requirements still apply.
2. **Find an ACC faculty sponsor for ACCESS or NRP Nautilus.** These are the strongest sustainable research-compute routes. Undergraduates cannot lead an ACCESS allocation themselves; an eligible faculty PI can add student users. A community college affiliation is not inherently disqualifying for ACCESS.

4. **Use Lightning's introductory credit for a GPU that fits**, if the account permits it. Free notebook GPUs from Kaggle/Colab are fallback resources, not a reliable home for the unchanged full matrix.

## What this experiment actually needs

The supplied ETA snapshot estimates **20.72 days remaining locally**, extrapolated from very small smoke training runs. It is not a measured full-training ETA and must not be used to promise a cloud speedup.

The repository uses Qwen3-8B and OLMo 3 7B, BF16 base weights, FP32 LoRA parameters, and a standard Transformers/PyTorch loop. README estimates **22–32 GiB** for short-context training. Target a **40 GB or larger GPU**, preferably 80 GB or larger. A 24 GB card needs a measured memory check; a 16 GB card does not fit the expected unchanged training recipe. Two 16 GB cards do not automatically form a 32 GB device: the loader calls `.to(device)` and implements no model sharding. P100/T4 also need dtype/backend compatibility checks rather than assuming the current BF16 configuration will work.

CUDA selection already exists in `scripts/common.py`. AMD ROCm PyTorch generally exposes GPUs through the same `torch.cuda` API, making AMD promising, but the ROCm build, BF16 operations, SDPA and both model families still require smoke validation. TPU and Intel XPU require backend changes; they are not ready-to-run substitutes.

- **Free Colab Pro for Education:** closed to new signups. Existing recipients may retain the remainder of their year. [Colab FAQ](https://research.google.com/colaboratory/faq.html)
- **Free Google AI Pro student trial:** currently offered to eligible US students for 12 months, with redemption through December 31, 2026. However, the Colab FAQ explicitly excludes free Google One trials, including promotional/extended trials, from premium Colab benefits. The student trial is useful for other tools but provides no premium compute budget for this matrix. [Student offer](https://support.google.com/googleone/answer/17422238), [Colab eligibility](https://research.google.com/colaboratory/faq.html)
- **SageMaker Studio Lab for a new account:** AWS announces it is no longer open to new customers starting July 30, 2026. Existing users can check their access; published legacy limits include four GPU hours per 24 hours and very limited storage. [AWS features notice](https://aws.amazon.com/sagemaker/ai/features/), [limits](https://docs.aws.amazon.com/sagemaker/latest/dg/studio-lab-overview.html)
- **DigitalOcean GitHub student $200:** GitHub's official partner changelog records its departure from the pack. Do not follow outdated student-credit lists. [Changelog](https://github.com/github-education-resources/Student-Developer-Pack-Current-Partners-FAQ/blob/main/SDP-changelog.md)
- **NVIDIA Academic Grant Program right now:** current page says applications are not being accepted; the listed PI requirement is full-time faculty at a PhD-granting institution. Not an immediate ACC undergraduate route. [Program](https://www.nvidia.com/en-us/industries/higher-education-research/academic-grant-program/)
- Free API quotas and chatbot subscriptions are not substitutes for training these exact checkpoints and evaluating our own LoRA adapters. Startup credits require genuine startup eligibility; do not count maximum advertised awards as available funds.

## How to turn an award into faster completion

Keep the existing local run progressing. First run the hardware check and a small fresh smoke experiment on each approved worker. Record actual peak memory, examples/second and evaluation throughput before recomputing ETA.

Split **complete independent training/evaluation jobs** across workers by student family, teacher dataset, seed and treatment/control arm. Each worker needs an isolated output directory. Generate each teacher dataset once and distribute its frozen, hashed files. The current matrix runner is sequential and is not a distributed scheduler; multiple copies must not write the same ledger or adapters.

Preserve exact model revisions, config, tokenizer and dataset hashes. Model manifest paths and plan paths are local-machine absolute paths and need deliberate reconstruction on Linux. Avoid resuming an MPS optimizer checkpoint directly on CUDA/ROCm: the checkpoint has backend-specific RNG state and the code restores it using the current backend. Start fresh independent jobs on cloud hardware, or implement and validate an explicit migration policy.

Checkpoint notebook work to durable storage within session limits. Do not silently quantize models to fit free 16 GB hardware: README explicitly avoids quantization as an experimental variable. A quantized experiment would need separate labeling and validation.

For credits attached to billable accounts, stop workers before credit expiry/exhaustion and account for persistent storage. Budget notifications alone are not hard spending caps. No speedup factor is claimed until we have a benchmark on the actual awarded device.
